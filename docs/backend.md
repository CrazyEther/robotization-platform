# API и приватные кабинеты

API Hono работает локально на `127.0.0.1:8787`; Cloudflare Worker использует тот же обработчик. Публичные маршруты `/api/v1`: `health`, `config`, `catalog`, `process-templates`, POST `diagnose`, `compare`, `economics`, `models`, `simulation/replay`, `simulation/flow`, `imports/validate`. Каталог — исследовательские записи с источниками; наличие в нём не подтверждает права на перепубликацию или готовность к закупке.

`config` возвращает только публичные URL/anon key Supabase. Service-role key не используется приложением. Закрытые маршруты требуют `Authorization: Bearer <Supabase access token>`; сервер проверяет пользователя через Supabase Auth, а запросы к PostgreSQL сохраняют его JWT. Без конфигурации кабинеты отвечают 503.

## Контракты кабинета

- GET/POST `organizations`: список доступных организаций / создание `{name}` и членства owner одной транзакцией.
- GET/POST `organizations/:orgId/scenarios`: список / сохранение `{name,payload}`.
- PUT `organizations/:orgId/scenarios/:id`: `{name,payload,expectedVersion}`. Конфликт версии возвращает 409. Каждое сохранение атомарно пишет неизменяемую историю.
- GET `organizations/:orgId/scenarios/:id/history` и `.../export`: история и JSON с версией схемы.
- POST `organizations/:orgId/invitations`: `{email,role:"editor"|"viewer"}`. Возвращает одноразовый token; письмо не отправляется. Токен хранится только как SHA-256, срок семь суток.
- POST `invitations/accept`: `{token}`. Принимает только вошедший пользователь с подтверждённым совпадающим email. Повторное принятие запрещено. Существующее членство не повышается и не понижается.
- POST `organizations/:orgId/imports`: provenance payload с `mappingVersion:"1"` в staging; POST `.../imports/:id/publish`: атомарная публикация владельцем. Публикация относится к каталогу организации и не раскрывается в общем публичном каталоге. GET `organizations/:orgId/catalog` возвращает версии публикаций.

Все таблицы защищены RLS, прямые записи от anon/authenticated запрещены. Записи проходят функции с `security definer`, фиксированным пустым search_path и явной проверкой `auth.uid()`. Viewer читает сценарии; editor изменяет сценарии и создаёт staging; owner также приглашает и публикует. Не реализованы удаление организации и передача владения: такие операции требуют отдельного контракта аудита и восстановления.

## Подключение и проверка

1. Запустить Supabase PostgreSQL либо создать проект. Применить `supabase/migrations/202609050001_platform.sql` через `supabase db push` к выбранному проекту или `supabase db reset` локально.
2. В Supabase Auth включить Google, добавить Client ID/Secret собственного OAuth-приложения; зарегистрировать callback Supabase у Google и точный URL сайта в разрешённых redirect URLs. Не разрешать wildcard на произвольные домены.
3. Настроить `SUPABASE_URL` и `SUPABASE_ANON_KEY` среды API. Для Worker использовать bindings/secrets окружения; перед deploy собрать `npm run build`. OAuth credentials не коммитить.
4. Выполнить `tests/rls-structure.sql` в PostgreSQL. `tests/rls-isolation.sql` принимает три существующих разных идентификатора auth.users и проверяет чтение viewer, запрет его записи и приглашений, невидимость чужой организации и истории, версии и атомарность истории; транзакция откатывается. Затем подтвердить живыми Google-пользователями вход, одноразовое приглашение и атомарность импорта. Структурный SQL тест сам по себе не доказывает эти сценарии.
5. Резервировать PostgreSQL средствами провайдера или `pg_dump` вне публичного репозитория. Восстановить в отдельный пустой проект, повторить RLS и проверку содержимого/истории. Резервные копии могут содержать персональные данные и приватные объекты.

Текущая реализация не подтверждает работоспособность облачного PostgreSQL, Google OAuth или восстановления до выполнения этих шагов на реальных доступах. Ограничение тела HTTP — 2 МБ; сценария в БД — 1,5 МБ. SQL повторно проверяет минимальные условия provenance при staging и публикации. Условия использования источника предоставляются ответственным за импорт; система не может сама подтвердить юридическую достоверность его заявления.
