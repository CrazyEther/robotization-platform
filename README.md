# Robot Investment Studio

Robot Investment Studio (RIS) — предынвестиционная среда для проверки сценариев роботизации на конкретной площадке. Основной рабочий путь теперь построен вокруг **Digital Twin Studio**, а не вокруг прежних SimPy/JaamSim-калькуляторов.

## Что работает сейчас

1. **Объект и рабочая нагрузка.** Шаблоны для склада, производства, медицинского учреждения и аэропорта.
2. **Каталог оборудования.** Источники и паспортные характеристики отделены от эксплуатационных допущений.
3. **Загрузка помещения.**
   - PNG/JPG/WebP — как масштабируемая подложка для ручной оцифровки;
   - JSON — как проверяемая геометрия помещения;
   - PDF/DXF/DWG можно прикрепить как исходный документ, но автоматический векторный импорт этих форматов пока не реализован.
4. **2D-редактор.** Стены, стеллажи, двери, зарядные станции, рабочие станции, лифты, точки A/B. Стены и стеллажи блокируют маршрут. Количество/вместимость зарядок влияет на число зарядных каналов.
5. **RIS Digital Twin `grid-agv/1.0`.** Собственный воспроизводимый движок:
   - задания поступают по заданному потоку;
   - несколько роботов распределяют задания;
   - движение выполняется по дискретной сетке помещения;
   - запрещено одновременное занятие одной внутренней ячейки двумя роботами;
   - моделируются погрузка/разгрузка, очередь, трафик, батарея, зарядка, холостой и гружёный пробег;
   - результатом является не только KPI, но и набор временных кадров движения роботов.
6. **2D replay + 3D view.** Анимация строится из траекторий того же запуска, который дал KPI. 3D-представление сделано на Three.js и использует ту же геометрию/позиции.
7. **Baseline vs robot.** Исходный процесс и парк роботов получают одинаковый поток заданий и одинаковую геометрию.
8. **CAPEX / OPEX / ROI / NPV / окупаемость.** Финансовый вывод блокируется, если один из сценариев не выполняет общий годовой план или денежные входы неполны.
9. **Экспорт.** JSON проекта содержит сцену, параметры, траектории, KPI baseline/robot и инвестиционную оценку.

## Запуск локально

Требуется Node.js 24+.

```powershell
git clone --branch feat/anylogic-scene-workspace https://github.com/CrazyEther/robotization-platform.git
cd robotization-platform
npm ci
npm run start:full
```

По умолчанию сайт доступен на:

```
http://127.0.0.1:8890
```

Python и Java для обычного запуска RIS Digital Twin больше не нужны.

Проверки:

```powershell
npm run typecheck
npm run lint
npm test
npm run data:verify
npm run build
npm run test:e2e
```

## AnyLogic

AnyLogic — **отдельный профессиональный адаптер**, а не скрытая замена текущему движку.

В репозитории есть:
- `packages/ris/cloud.ts` — контракт AnyLogic Cloud/Open API с обязательными входами геометрии, робота и процесса и обязательными выходами KPI/траекторий;
- серверные маршруты `/api/v1/ris/cloud/status`, `inspect`, `run`;
- fail-closed проверка: RIS не выдаёт результат AnyLogic, если опубликованная модель/версия/выходы не подтверждены;
- `scripts/setup-anylogic-mcp.ps1` — установка закреплённой версии стороннего AnyLogic PLE MCP в изолированное окружение.

Сторонний PLE MCP полезен для генерации простых `.alp`-моделей Source/Queue/Delay/Sink. **Он не реализует мобильную навигацию, помещение и AGV digital twin**, поэтому не считается профессиональным движком RIS.

Для реального выполнения RIS-модели через AnyLogic потребуется опубликованная модель, принимающая контракт RIS и возвращающая `risTraceJson` + `risKpisJson`. Пока такой опубликованный экземпляр не подтверждён, интерфейс честно показывает AnyLogic как неподключённый.

## Ограничения текущего Digital Twin

Это уже исполняемая модель движения, но пока не физический digital twin уровня полностью откалиброванного AnyLogic/FlexSim-проекта:

- один уровень помещения;
- ортогональная сетка 1 м;
- один основной транспортный поток A → B на сценарий;
- нет кинематического радиуса разворота и footprint конкретного робота;
- нет safety scanner zones и сертификационной проверки проходов;
- двери и лифты пока являются объектами сцены, но не динамическими ресурсами;
- 3D — геометрическое представление, а не физический движок;
- автоматическое распознавание стен из PNG/PDF/CAD ещё не реализовано;
- стоимость оборудования и реальный baseline должны подтверждаться пользователем/предприятием.

Поэтому RIS сейчас предназначен для **предынвестиционной инженерной оценки и сравнения сценариев**, а не для автоматического утверждения проекта без последующей инженерной валидации.

## Архитектура расширения

- `packages/ris/digitalTwin.ts` — исполняемый транспортный движок и финансовое сравнение.
- `packages/ris/scene.ts` — операции над геометрией/сценой и импорт.
- `apps/web/DigitalTwinStudio.tsx` — единая студия plan → edit → execute → replay → compare.
- `apps/web/Scene3D.tsx` — Three.js представление сцены.
- `packages/ris/cloud.ts` — адаптер профессионального AnyLogic Cloud.
- `data/catalog.json` — источник оборудования.
- `tests/digital-twin.test.ts` и `tests/e2e/workflow.spec.ts` — вычислительные и сквозные доказательства.

Новые отраслевые сценарии добавляются через сценарный слой и шаблоны процесса; базовый движок не должен быть переписан под каждый новый объект.
